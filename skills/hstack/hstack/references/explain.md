# Explain

Use this to explain how something works or why it is shaped that way. Do not edit.

1. Read the code and the git history before you name a cause.
2. Walk one path a caller takes. Name the module that owns the rule.
3. If an evidence tool is already connected, use it for issues, docs, or errors. Do not ask the user to connect one.
4. Add a diagram only when it changes the explanation. Then follow `references/diagram.md`.
5. Stop when a newcomer could follow the path.
