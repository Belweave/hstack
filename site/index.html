The index stays small.

Hermes reads every skill description on each turn. HStack keeps one short router there. A playbook loads only when the task needs it. Counts use Hermes's estimator, ceil(bytes / 4).

Twelve skills.

One line in the index. The body loads when you ask for that skill.

One router. One playbook.

/hstack is the skill to remember. It opens the route catalog and loads one playbook. Everything else stays on disk.

  1. frameDeciding what to build. Load reframe, then stop or hand off.
  2. featureNew or changed behavior. Shape it, implement it, prove it.
  3. fixSomething is broken. Use systematic-debugging, then prove the fix.
  4. checkThe diff needs a hard look. Council only if you asked for other models.
  5. landThe work should become a pull request. Load ship.

A one-line edit does not need a playbook. If you name another HStack skill, that skill loads and the router steps aside.

Install

macOS and Linux. The script is safe to run twice. It only replaces a tree it created.

Install

curl -fsSL https://hstack.sh/install | sh

Dry run

curl -fsSL https://hstack.sh/install | sh -s -- --dry-run

Uninstall

curl -fsSL https://hstack.sh/install | sh -s -- --uninstall

From a checkout of the repo, sh install.sh installs the skills next to the script. HSTACK_BASE_URL points the curl form at another host, which is how you try a *.vercel.app URL before DNS. Optional add-ons stay off until you pass --with.
